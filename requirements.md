# Security Requirements

| Requirement ID | Requirement/User Story Description | Priority | Complexity |
|---|---|---|---|
| SR-01 | **MFA (TOTP) for all AEC staff and delegate accounts.** As an AEC staff member or state Commissioner's delegate, I must enter a time-based one-time password (TOTP, RFC 6238) in addition to my password before a session is issued, so that a phished or stolen password alone cannot give an attacker access to enrolment, candidate or result functions. | High | Medium |
| SR-02 | **Role-based access control with least privilege, enforced server side.** As the platform owner, I need every request authorised on the server against the caller's role, with deny by default, so that a user can perform only the actions their role requires and hiding buttons in the UI or altering client requests cannot bypass permissions. | High | Medium |
| SR-03 | **Login protection: Argon2id hashing, lockout and rate limiting, all attempts logged.** As the platform owner, I need passwords stored only as salted Argon2id hashes, accounts temporarily locked after repeated failed logins, login requests rate limited per account and per IP, and every login attempt logged, so that brute-force and credential-stuffing attacks are slowed, and a database leak does not expose usable passwords. | High | Medium |
| SR-04 | **Tamper-evident, hash-chained audit log for all admin and roll changes.** As an auditor, I need every administrative action and electoral-roll change recorded in an append-only log in which each entry includes a hash of the previous entry, so that any edit, deletion or reordering of past entries is detectable by a verification routine and each change can be traced to a user, time and before/after value. | High | High |
